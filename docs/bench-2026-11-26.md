# Bench session 2026-11-26: reference-hold calibration

Status: read-only record. No firmware, gains, limits or wire protocol were
changed. All trials ended with `home 0` and `estop`; no push was performed.

## Tooling used

- `ref_hold_cal` with `--torque-source applied`, recording requested
  (`cmd_left_units`, `cmd_right_units`) and applied (`al`, `ar`) commands.
- `jbot-analyze` for axis consistency, pitch-law fit, breakaway and oscillation.
- `command_path` for applied-word reporting delay.
- `send` example for `ping`/`stat` health checks.

## Measurements

- Axis check is `consistent` for pitch in sessions 6-8; one session during a
  supported baseline was `UNPAIRED` and is not used for control conclusions.
- `command_path` on session 1 reports 15 gradual command steps with 6-7 ms
  applied-word reporting delay. This is feedback-frame quantization, not
  actuator transport delay.
- Free spin-up identification from `docs/precision-control-2026-11-25.md` gives
  210-241 units/Nm, close to the compiled 200 units/Nm. The 3.2x torque error
  hypothesis remains unsupported.
- Loaded breakaway is roughly 50-63 units without per-wheel compensation. The
  lower 13-17 unit estimate came from fitting the *requested* torque while
  dither and `cal` were active. `jbot-analyze` now prefers the applied per-wheel
  commands when those columns exist; with them the brackets overlap (stuck up
  to 62 units, moving from 5 units), so none of these sessions yields a usable
  calibration.
- Fitted pitch `kp` stayed between 0.4 and 1.0 Nm/rad against a 5.39 Nm/rad
  stability floor. The fits are dominated by supported baselines and are not
  sufficient to re-derive the controller.

## Decision

Runtime tuning is closed: `pscale`, `slew`, `db`, `cal` and `dither` were each
varied in isolation and none produced a single stable hold. WP0 measurement is
the next gate. The required lever arm, force gauge or known hanging mass was
not available in this session, so WP0 is blocked on tooling, not on code.

The release injects a large rate spike in every session; even with a fast
moment ramp the law never settles inside the 2 deg / 8 dps window. Automatic
profile search is closed as well. A clean release fixture and WP0 measurement
are prerequisites before any further balance trial.

## Next PC tool

`crates/jbot_console/src/bin/auto_tune.rs` was prepared but not run. It searches
a bounded `pscale`/`slew` grid using runtime commands only; it never sends
`zero` or `level`, preserves an upright calibration, and scores each trial with
the same tilt/rate/travel guards. A profile is accepted only when the body
settles within 2 degrees of `home` with turning wheels for 500 ms. It writes a
CSV and a JSON verdict per profile and always ends with `home 0` and `estop`.
Running it is a new hardware action and needs explicit approval.

## Do not

- Do not repeat the same runtime profiles: the artifacts above are the record.
- Do not lower the travel, rate, tilt or fall guards to make a run pass.
- Do not change `PlantParams::NOMINAL` or `tmax` without a measured torque
  budget and a recording that justifies the change.
